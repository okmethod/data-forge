# 国勢調査 e-Stat 帳票マップ

**このドキュメントの役割：** 精製の**取得元**である e-Stat（国勢調査, `statsCode=00200521`）にどんな帳票（統計表）があり、どういう構造を持ち、**どの帳票がどのデータセットのソースになるか**を 1 枚に集約する。ソースの対応づけは帳票の構造（粒度・カバレッジの非対称）で決まり、その根拠を §2・§4 に示す。  
**精製後データの仕様**（出力スキーマ・データセット一覧・利用方法）は各データセット docs（[population.md](population.md) / [population_by_age.md](population_by_age.md) / [population_by_age5.md](population_by_age5.md) / [daynight_population.md](daynight_population.md) / [households.md](households.md) / [family_type.md](family_type.md)）が正典。  
ライセンス・商用可否は[data_catalog.md](data_catalog.md)。
地域集約の仕組みは [area_master.md](area_master.md)。

> **読み分けの指針：** 「statsDataId・帳票の粒度・年ごとのクセ・ソース対応の根拠」を知りたい → 本書。
> 「出力列・行数・CLI コマンド」を知りたい → 各データセット doc。

## 1. 国勢調査の集計体系（親子関係・混同注意）

国勢調査は 1 回の調査から**複数の「集計」が段階リリース**される。  
名称が似て紛らわしいので先に地図を示す。

| 集計（親）                               | 内容                                 | data-forge での対応                |
| ---------------------------------------- | ------------------------------------ | ---------------------------------- |
| **人口速報集計**                         | 総人口・世帯数のみ（調査翌年に速報） | 速報系列のソース                   |
| **人口等基本集計**（旧称 第1次基本集計） | 男女・年齢・配偶関係・世帯・住居など | **主ソース**                       |
| 就業状態等基本集計（旧称 第2次基本集計） | 労働力状態・産業・職業               | 労働力率・産業・職業を採用（§3-6） |
| 従業地・通学地集計                       | 昼夜間人口・通勤通学流動             | 昼夜間人口のソース                 |
| 移動人口集計 / 人口移動集計              | 5年前常住地・転出入                  | 不採用（§3-7）                     |

> 「第1次基本集計＝人口等基本集計」「第2次基本集計＝就業状態等基本集計」は**別物**。
> 労働力・産業・職業は第2次に属し、人口等基本集計には**無い**。

## 2. 決定的な区別：「各回のありのまま」 vs 「年跨ぎ編纂の時系列」

同じ「男女別人口」「年齢別人口」でも、e-Stat には **2 系統**の帳票が存在する。  
**この違いがソース対応の核心**であり、両者は**地域カバレッジが非対称**である。

- **A. 各回の基本集計**: 合併前の旧自治体まで持つ生データ
  - その年に存在した**全単位**を列挙。合併市を**旧構成自治体へ分解した行**（旧市区町村）を含む
  - 全国／都道府県／市区町村＋旧市区町村＋市部郡部＋人口集中地区(DID) 等
  - **年ごとに設計が違う**（後述の4変種）
  - 旧市区町村アトム＝**合併畳み込み（`aggregate_to_base`）の材料**を持つ

- **B. 時系列データ製品**: e-Stat が**年跨ぎ比較用に目的別に再編纂**した製品（時系列データ 男女、年齢、配偶関係、等）
  - **現在境界に揃えた比較用**。**旧市区町村を持たない**（分解行なし）
  - 表により全国 / 都道府県 / 市区町村。年齢の**市区町村まで下りるのは 3 区分だけ**
  - 全年**完全同型**（連番 statsDataId・軸コード共通）
  - 1 本の cleaner で全年処理でき、綺麗な連続時系列

## 3. 帳票インベントリ

> 全表を **| 年 | statsDataId | 帳票名 | 粒度・特徴 | 精製先 |** の同形で並べる。
> 時系列版（系統 B・daynight）は 1 帳票が複数年をまたぐため、**年＝範囲・statsDataId＝連番/リスト**として 1 行に集約する。
>
> **「精製先」列＝この文書の採否ビュー**（別途の採用表は作らない）。採否の判断を同じ行の「粒度・特徴」＝構造理由と同居させる。3 状態で読む：
>
> - **採用**＝データセット doc へのリンク（例 [population](population.md)）。採用済みソースの正典は docs/README + datasets.py。
> - **候補**＝`—（★採用候補: 理由）`。未実装だが実装予定。実装で精製先が埋まれば当該族の節へ定着する。
> - **不採用**＝`—（理由）`。ソースにしない帳票と、その理由（再調査不要の記録）。

## 4. ソース対応の根拠（構造的理由）

### 4-1. population と population_by_age で**ソースが違う**理由

- **population（男女別総人口）は各回の男女別人口表（A）を使う** … 旧市区町村(level7)アトムが必要だから。
  これは合併畳み込み `aggregate_to_base`＝「合併をまたいで正しく畳んだ市区町村の長期時系列」
  （data-forge の価値の芯）の**材料そのもの**。B には無い。
- **population_by_age（年齢3区分）は時系列の年齢3区分表（B）を使う** … 1980-2020 が全年同型で
  市区町村まで下り、**cleaner 1 個**で済むから。`cat01=100`（年齢総数）で絞れば population の
  総人口を値一致で再現できる。

### 4-2. 各回の男女別人口表（A）と時系列3区分表（B）は非冗長（＝カバレッジ非対称）

総人口は A と B で全キー一致するが、**B は A の厳密な部分集合**で旧市区町村(level7)を持たない。
2005-2020 では毎年 2,000 超の level7 アトムが A にのみ存在する（§3-1）。
ゆえに **A は B で代替できず、両表はそれぞれ固有のデータを運ぶ**（A＝level7 アトム、B＝綺麗な連続時系列）。
＝A の男女別人口表 5 本は冗長ではない。

> 例外として **2000 表だけは level7 を持たず**、B の3区分表と完全一致する。この 1 例のみを見て「A は B で代替可能」と一般化すると誤る（2005 以降は level7 が A にしか無い）。

### 4-3. 5歳階級・配偶関係の粒度

- 5歳階級の**市区町村×全年**時系列は e-Stat に**存在しない**（B の年齢表で市区町村まで下りるのは 3 区分のみ）。
- **全国・都道府県**なら 5歳階級が 1920-2020（一世紀）を単一 ID で持つ（0003410380/381）。
  合併の影響を受けない 47 コード固定で area master 不要＝低コスト。→ [population_by_age5](population_by_age5.md) のソース。
- 配偶関係（0003410382）も全国のみの同型表。
- 市区町村5歳階級は各回集計に 1980 から在るが年ごと別 ID・別軸交差。総数は 1980-2020 全年で市区町村フルに取れる（1990/1995 の総数は各歳表 00401=0000031401/0000032219、2000/2005 は各歳表 0000032965/0000033783 から5歳再掲を抽出）。日本人は 1990/1995（5歳階級表 006）と 2000-2020 で取れる（§3-3 に全 ID とマトリクス）。

### 4-4. 速報の位置づけ

2025 の**人口速報集計**（総人口・世帯数のみ）は基本集計とは**別系統**。確定系列には素で混ぜず、
`data_status=preliminary` 来歴列で暫定であることを明示して後段で継ぎ足す（確定版が出た時点で統合し速報は破棄する）。
詳細は [population.md](population.md) の「速報値の扱い」。

# e-Stat 国勢調査 帳票カタログ

このドキュメントの役割は、**取得元＝入力側データセットの正典**。  
e-Stat（国勢調査, `statsCode=00200521`）の各帳票（統計表）の構造・採否（採用/不採用/候補）・精製先、および statsDataId・粒度・年ごとの軸クセ・ソース選定の根拠を、「取得元の事実」としてここで確定する。
ソース対応は帳票構造（粒度・カバレッジの非対称）で決まり、その根拠は「2 つの帳票型」の節に示す。

**関連ドキュメント**:

- **精製先＝出力側データセットの正典**: [forged-dataset-catalog.md](../distributions/forged-dataset-catalog.md)
- **ライセンス・商用可否**: [data-provider-catalog.md](data-provider-catalog.md)
- **地域集約の仕組み**: [area_master.md](../distributions/area_master.md)

> 帳票カタログは、全表を **`| statsDataId | 帳票名 | 型 | 年 | 粒度・特徴 | 精製先 |`** の同形で並べている。  
> `粒度・特徴` 列は先頭にその表の最も細かい地理 level を置く（`全国`／`都道府県`／`市区町村`）。

## 参考：国勢調査の集計体系（親子関係・混同注意）

国勢調査は 1 回の調査から**複数の「集計」が段階リリース**される。  
各「集計（親）」はさらに複数の**帳票（統計表＝statsDataId 単位）**を含み、本カタログが列挙・採否を判定する単位はこの帳票としている。

| 集計（親）                                   | 内容                                 | data-forge での対応                                  |
| -------------------------------------------- | ------------------------------------ | ---------------------------------------------------- |
| **人口速報集計**                             | 総人口・世帯数のみ（調査翌年に速報） | 速報系列のソース                                     |
| **人口等基本集計**（旧称 第1次基本集計）     | 男女・年齢・配偶関係・世帯・住居など | **主ソース**                                         |
| **就業状態等基本集計**（旧称 第2次基本集計） | 労働力状態・産業・職業               | 労働力率・産業・職業を採用（就業状態等基本集計の節） |
| **従業地・通学地集計**                       | 昼夜間人口・通勤通学流動             | 昼夜間人口のソース                                   |
| **移動人口集計** / **人口移動集計**          | 5年前常住地・転出入                  | 不採用（移動人口集計の節）                           |

- 労働力・産業・職業は第2次（就業状態等基本集計）に属し、人口等基本集計には無い。混同に注意。

## 前提：2 つの帳票型（回次別帳票 / 回次跨帳票）

同じ「男女別人口」「年齢別人口」でも、e-Stat には **2 種類**の帳票が存在する。  
**この違いがソース対応の核心**であり、両者は**地域カバレッジが非対称**である。

- **回次別帳票（各回の基本集計）**: 調査回ごとに別 statsDataId の生データ。合併前の旧自治体まで持つ
  - その年に存在した**全単位**を列挙。合併市を**旧構成自治体へ分解した行**（旧市区町村）を含む
  - 全国／都道府県／市区町村＋旧市区町村＋市部郡部＋人口集中地区(DID) 等
  - **年ごとに設計が違う**（後述の4変種）
  - 旧市区町村アトム＝**合併畳み込み（`aggregate_to_base`）の材料**を持つ
  - パイプラインでは year 軸で**縫合**して **`StitchedDataset`** を精製し、**ミクロ層（市区町村粒度・近年）データセット**として利用する

- **回次跨帳票（時系列データ製品）**: 1 帳票が複数回（複数年）を跨ぐ、e-Stat が**年跨ぎ比較用に目的別に再編纂**した製品
  - **現在境界に揃えた比較用**。**旧市区町村を持たない**（分解行なし）
  - 表により全国 / 都道府県 / 市区町村。年齢の**市区町村まで下りるのは 3 区分だけ**
  - 全年**完全同型**（連番 statsDataId・軸コード共通）
  - 1 本の cleaner で全年処理でき、綺麗な連続時系列
  - パイプラインでは area 軸で**射影**して **`ProjectedDataset`** を精製し、**マクロ層（都道府県粒度・長期）データセット**として利用する

### ファクトによってソースが違う（ソース対応の根拠）

同じ人口でも、**ファクト（精製先データセット）が求める粒度**によって回次別／回次跨のどちらを採るかが決まる。

- **男女別総人口（population）＝回次別帳票（各回の男女別人口表）**: 合併畳み込み `aggregate_to_base`（合併をまたいで畳んだ市区町村の長期時系列＝data-forge の価値の芯）の材料である旧市区町村アトムが要り、回次跨帳票には無いため。
- **年齢3区分（population_by_age）＝回次跨帳票（時系列の年齢3区分表）**: 1980-2020 が全年同型で市区町村まで下り **cleaner 1 個**で済む。`cat01=100`（年齢総数）で絞れば population の総人口を値一致で再現できる。

### 非冗長（カバレッジ非対称）＝検算オラクル

総人口は回次別帳票と回次跨帳票で全キー一致するが、**回次跨帳票は回次別帳票の厳密な部分集合**で旧市区町村を持たない。  
2005-2020 では毎年 1,401〜2,121 の旧市区町村アトムが回次別帳票にのみ存在する（男女別人口の節。level7 で符号化されるのは 2020 のみ・2005-2015 は level4「(旧…)」）。
ゆえに **回次別帳票は回次跨帳票で代替できず**、男女別人口表 5 本は冗長ではない（回次別＝level7 アトム／回次跨＝綺麗な連続時系列を、それぞれ固有に運ぶ）。

例外として **2000 表だけは旧市区町村を持たず**、回次跨帳票の3区分表と完全一致する（2005 以降は旧市区町村が回次別帳票にしか無い）。
この 1 例のみを見て「回次別帳票は回次跨帳票で代替可能」と一般化すると誤るため注意。

裏を返せば、両表が総人口で全キー一致することは**クロスファクト検算のオラクル**（県 rollup vs 回次跨帳票の県で diff=0 を各データセットで検証）になる。

このオラクルを保つため、**各 fact は自前の回次跨帳票を独立に取得**し、cleaned 出力を他 fact の材料に使い回さない（回次別と回次跨が同じ生値から出ると diff=0 が自明化し検算が空になるため）。
各 fact 節ではこの原則を再掲せず、当該回次跨帳票の固有クセ（47県・全国行の有無・出力シェイプ等）のみ記す。

### 兄弟ファクトの実現可能性（時系列データ製品の市区町村カバレッジ）

**「星座に足す候補の話題 × それを市区町村×経年で安く作れるか」の判定表**（次に何を作れるかのソース選定ロードマップ）。
安く作れるかは **回次跨帳票（e-Stat「時系列データ」製品）が市区町村まで下りて存在するか**でほぼ決まる（経年比較用に整形済み＝cleaner 1 個で足りる）。
無い話題は回次別帳票の自前ハーモナイズ（男女別人口 本体並みの高コスト）になる。

| 話題（ファクト候補） | 市区町村×経年         | 根拠＝e-Stat「時系列データ」グループ              | 状態                                                                          |
| -------------------- | --------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------- |
| 年齢3区分×男女       | ○                     | 男女，年齢，配偶関係                              | ✅ 実装済 → [population_by_age.md](../distributions/population_by_age.md)     |
| 昼夜間人口           | ○（1990-2020）        | 従業地・通学地                                    | ✅ 実装済 → [daynight_population.md](../distributions/daynight_population.md) |
| 配偶関係             | △（時系列は全国のみ） | 男女，年齢，配偶関係（※配偶関係表は市区町村なし） | 見送り（回次別帳票の自前ハーモナイズ＝高コスト）                              |
| 労働力・産業・職業   | ×（都道府県止まり）   | 労働力状態，就業者の産業・職業                    | 未（同上）                                                                    |
| 世帯                 | ×（都道府県止まり）   | 世帯                                              | 未（同上）                                                                    |

> グループ名は e-Stat の `STATISTICS_NAME`（例: 「時系列データ 男女，年齢，配偶関係」）に一致。
> 同じグループでも**表単位で地域粒度が違う**点に注意（例: 「男女，年齢，配偶関係」グループの年齢・男女表は市区町村まであるが、配偶関係表は全国のみ）。

> 「人口等基本集計」という名称は 2010 年以降だが、等価物「第1次基本集計」は 1980 まで遡って存在する。
> ただし年あたり数十〜数百のクロス集計表の集合で **era 毎にスキーマが違い経年比較用に整っていない**。
> 経年比較したい話題は**まず「時系列データ」製品（回次跨帳票）を優先**し、無い話題だけ回次別帳票の自前ハーモナイズを覚悟する。

#### 年別の特記（表探索の罠・同型流用）

以下 3 年代は各回表の構造が特殊で cleaner が固有分岐する。

##### 1990 / 1995 — 総人口と日本人が別表

- **罠**: 総人口は**各歳表 00401**（1990=`0000031401` / 1995=`0000032219`、年齢軸に 5歳再掲 T01/200-219/500=100歳以上/900=不詳を内包＝2000 の `0000032965` と同型）、日本人は**5歳階級表 006**（`0000031405`/`0000032223`）。5歳階級"表"だけを探すと総人口（各歳表側）を見落とす（2005 も同型）。
- **採用**: 総数=各歳表00401 と日本人=5歳階級表006 の **2 Dataset を同年 union**（2000/2005 は単一表に国籍軸ありで両出し＝構造が違う）。
- **cleaner**: `clean_1990_1995_total`（総数）＋ `clean_1990`/`clean_1995`（日本人）。**総数カバレッジ＝1980-2020 完全**（日本人の 1980/85 欠は表自体が無く恒久）。

##### 2000 — 単一の各歳表

- **却下**: 市規模で分かれる下記2つの5歳階級表は結合しても全市区町村を覆えない。両表の収録範囲が特別区・県庁所在市で食い違っており、どちらにも入らない狭間（人口20-50万となる16の特別区、人口20万未満となる30の県庁所在市）が生じ、全国で約476万人が欠落する。

#### 実装ルールと検算

**検算**: 全年で 全国＝公表値一致・県 rollup vs 回次跨帳票の県(`0003410381`) 47県 diff=0（＝C1）・男女保存を全 area で検証済。
年齢保存は**不詳の有無で条件分岐**する（本旗艦は不詳を導出注入しない＝下記「不詳の扱い」）: 不詳コードがある年は `Σ5歳+不詳==総数`、
無い年（1990/1995/2005）は `Σ5歳<=総数`（2005 は「不詳を除く」表ゆえ `Σ5歳==総数` が恒等成立）。
**各検算の定義は [data-quality-assurance.md](../data-quality-assurance.md) が正典**。
ソース選定根拠は本 doc で説明するが、具体値についてはテストコード（期待値）に置き、実測は検証タスク実行時に得る。この節には再掲しない。

- **年ごとに軸割当もコード体系も違う（getStatsData 実測が正典）**: cleaner は年別（`age5_municipality.py` の `clean_1980`〜`clean_2020`）。標準軸は男女=cat02／年齢=cat03。**2015 は男女=cat03(0000/0010/0020)・年齢=cat02(0000/1180-1490)** と入れ替わる（1995 も男女=cat03／年齢=cat02 の入替＝表では `★軸入替`）。getMetaInfo と食い違うので getStatsData の実コードで確定する。**level7（旧市区町村＝合併畳込材料）は 2020 のみ持つ**（無くても aggregate_to_base は成立）。国籍コード: 2010=cat04(000/100)・2015=cat04(0000/0150)・2020=cat01(0/1)。不詳コード: 1980=022/1985=023/2010,2015=999/2020=22（1990/1995 は不詳コード無し）。1980 の `0000030127`（5歳階級表）は 001-021＋022不詳の 22 区分で 100歳以上まで持ち 2020 と同型。
- **令和型 level4/6 の各回表は `muni_levels={4,6}` の明示上書きが必須**: 対象＝1980/1985 の各歳表（`0000030127`/`0000030449`）・1990/1995 の日本人5歳階級表006（`0000031405`/`0000032223`）・2000/2005 の各歳表。省くと `extract_atoms` が level3 の郡/支庁など中間集計を葉に拾い市区町村フルに達しない。
- **不詳の扱い（導出注入は"母集団が閉じる表"だけ）**: 系統B age5 / 3区分時系列は総数と階級が同一母集団ゆえ `総数−Σ` で不詳を注入する。本ミクロ系列（各歳表）は国籍カバレッジが非対称で総数と5歳階級の母集団保証が弱く、導出不詳が基底差の残差を含みうる（偽の不詳）ため**注入しない**＝不詳の実コードがある年はそのまま採り・無い年（1990/1995/2005）は空。age5 との非対称はバグでなく本原則の帰結。
- クロスファクト検算 C1 は総数スライスのみ照合するため、令和型各回表で日本人スライスの `muni_levels` override 欠落は検知できない点に注意。

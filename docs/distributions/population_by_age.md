# population_by_age — 国勢調査 年齢3区分×男女別人口（設計）

国勢調査（e-Stat）の **年齢3区分（年少0-14／生産15-64／老年65+）× 男女** 別人口を、
全国／都道府県／市区町村の粒度で 1980〜2020 の全年について精製するデータセット群。
高齢化の 45 年連続時系列を提供する。

> cleaner=`clean_population_by_age`（全年1個）／datasets 9表＋`population_by_age_timeseries`。combine は `grain` 引数で、area 集約（`aggregate_to_base` / `crosswalk`）は分類軸コード列（`*_code`）の自動判別で後方互換に一般化（`--join aggregate_to_base` / `crosswalk` が by_age でも通り、集約後も年齢保存・男女保存が実データで違反0＝2020 総人口 126,146,099 一致）。
> パイプライン全体設計は [pipeline-architecture.md](../pipeline-architecture.md) を参照。

---

## なぜ別データセットにするのか（星座型アーキテクチャ）

`population`（男女別総人口）と `population_by_age` は **grain が違う別ファクト**であり、
1 つの表に詰めない。人口（person×age×sex）・世帯（household）・就業者（worker）はそれぞれ
別 grain なので、**共有ディメンション（area master / time / sex / age）＋ 目的別ファクトの星座
（fact constellation）** として横に並べる。既に構築済みの **area master（アトム軸スタースキーマ）が
共有ハブ**として効く。

> **なぜ 1 ファミリーで済むか:** 現行 `population` は年ごとに設計の異なる複数の統計表を各年 cleaner で
> ハーモナイズするが、**「年齢（3区分），男女別人口及び年齢別割合」表は単一ファミリーで 1980〜2020 全年を
> 同一軸でカバー**する（下表）。この表は `population` が 1980-1995 で使う表（0003412413〜416）の ID 連番の続きで、
> `cat01=100`（年齢総数）で絞れば総人口をビット一致で再現できる。→ `population_by_age` は **cleaner 全年 1 個**で済む。

> 年齢不詳は下記の導出第4区分で明示保持する（補完版は将来の別バリアントとして任意）。

## 都道府県 世紀マクロ（回次跨帳票・1920〜2020）

`population_by_age_prefecture` / `population_by_age_prefecture_timeseries`（cleaner=`clean_by_age_prefecture`）は、
上記の市区町村ミクロ（各回別ID・1980〜）とは**別ソースの都道府県マクロ**で、5歳階級の
`population_by_age5_prefecture` と同じ役回り（回次跨帳票 raw を1920まで遡る世紀マクロ）。

- **ソース＝0003410383**「年齢（3区分）別人口及び年齢別割合 － 全国，都道府県（大正9年～令和2年）」。
  軸＝`tab`(1060=実数/105=割合)・`cat01`(年齢3区分 100総数/**105**=0-14/120=15-64/130=65+)・
  `area`(全国+47県)・`time`(1920〜2020)。**男女軸を持たない（総数のみ）**＝高齢化率の物語は総数で充足。
  2015/2020 は不詳補完版(time 末尾000010)が併存するため通常版(000000)へ統一。
- **出力**＝ミクロと同じ10列。`sex` は総数固定。`age_class_code` はミクロ（`AGE_TS`）と同一ターゲット
  (`0/1/2/3/9`) へ揃える（0-14 はミクロ=110・本表=105 とコードは違うが写像先は共通）。
- **全国(00000)は落とし47都道府県のみ**（全国=Σ県で復元）。
- **クロスファクト**：1980-2020 の重複年は市区町村ミクロの県 rollup と一致（唯一の差＝東京都1980の
  +37人＝特別区部の区未定分＝回次跨帳票側が正しい県総数）。高齢化率 1920=5.3% / 1980=9.1% / 2020=28.7%。

> **fact 独立取得**：このマクロは 5歳階級を集約して作らず、3区分の自前の回次跨帳票(0003410383)から
> 独立に取得する。cleaned 出力を別 fact の材料にしないことで、クロスファクト検算（5歳畳込==3区分 等）を
> 「定義的に真」でなく実効の検算オラクルに保つ。

## 出力スキーマ

grain = **area × year × sex × age_class**。`population` の 8 列に age_class の 2 列を足した 10 列。

| 列               | 型   | 説明                                                                                   |
| ---------------- | ---- | -------------------------------------------------------------------------------------- |
| `area_code`      | str  | 地域コード（JIS）                                                                      |
| `area_name`      | str  | 地域名                                                                                 |
| `area_level`     | int  | 階層（1=全国 / 2=都道府県 / 4=市 / 5=政令市の区 / 6=市区町村 / 7=旧市区町村）          |
| `sex_code`       | str  | 男女コード（0=総数 / 1=男 / 2=女）                                                     |
| `sex`            | str  | 男女名称                                                                               |
| `age_class_code` | str  | 年齢区分コード（0=総数 / 1=年少 / 2=生産年齢 / 3=老年 / 9=年齢不詳）                   |
| `age_class`      | str  | 年齢区分名称（総数 / 年少人口(0-14) / 生産年齢人口(15-64) / 老年人口(65+) / 年齢不詳） |
| `year`           | int  | 調査年                                                                                 |
| `population`     | int  | 人口（欠損は null）                                                                    |
| `is_current`     | bool | 現存自治体か（level 7=旧市区町村は false）                                             |

出力ファイル（`.parquet` / `.csv` / `.sqlite` / `.meta.json`）と役割は `population` と同一
（[population.md](population.md#出力ファイルdataprocessedstem) 参照）。SQLite テーブル名は `population_by_age`。

### 年齢不詳（age_class_code=9）は導出行

**時系列ファミリーの `cat01` は 総数/年少/生産/老年の 4 コードのみで、「年齢不詳」は独立コードとして存在しない。**
近年は不詳が無視できない（実測・東京都の 総数−3区分合計 ＝ 2000:46,848 → 2020:428,739 と経年増加）。
そのため **不詳 = 総数(100) − (年少 + 生産 + 老年)** を計算し、`age_class_code=9` の行として注入する。
これにより **年少 + 生産 + 老年 + 不詳 == 総数** が全年・全地域で恒等的に成立（人口保存が閉じる）。

## 再利用する資産（既存パイプラインとの差分だけを設計）

「兄弟ファクトを足す」＝ **横展開のコストを最小化**する。既存資産の再利用可否:

| 資産                                            | 再利用   | 差分                                                                                                                         |
| ----------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `transform.to_tidy` / `extract_meta`            | そのまま | ソース非依存。変更なし                                                                                                       |
| `population.clean_population`                   | 一般化   | `cat01=100` で捨てていた年齢軸を**保持**する `clean_population_by_age` を追加（下記）                                        |
| `population._prepend_national_from_prefectures` | そのまま | 全国行なしは同じ問題。都道府県合計から復元（age_class 別に group）                                                           |
| `combine.combine_years`                         | 小改修   | `GRAIN` に `age_class_code` を追加（grain をパラメータ化）。`_grid` の cross に age を追加                                   |
| area master（atoms/events/aggregate/reconcile） | 一般化   | 集約・保存検査を分類軸コード列（`*_code`）自動判別に一般化（キーは手足ししない）。events は JIS の事実なので**そのまま共有** |
| `io.export.export_all`                          | そのまま | `index_columns` を `[area_code, sex_code, age_class_code, year]` にするだけ                                                  |

### cleaner の一般化（要点）

`clean_population_by_age(tidy)`:

1. `tab=020`（人口）で絞る。
2. `cat02`（男女, SEX_2005 と同一コード）→ `sex_code` / `sex`。
3. `cat01`（年齢, 100/110/120/130）→ `age_class_code`（0/1/2/3）/ `age_class`。**`cat01=100` で捨てない。**
4. 全国行を都道府県合計から復元（age_class × sex 別に集計）。
5. **不詳行（age_class_code=9）を 総数−(1+2+3) で導出注入**。

現行 `clean_population`（男女だけ抜く 8 列版）は `population` 用に残す。
`clean_population_by_age` は「同じ入力パースを共有しつつ age を落とさない」拡張であり、
**正規化の契約は変わらず「共通の出力スキーマへの写像」**（[population.md](population.md#年ごとのスキーマ差) の原則を継承）。

### area master（合併をまたぐ集約）はそのまま効く

`population_by_age` も年をまたぐと市町村合併で地域集合が変わる。**area master は age に非依存**
（events は JIS コードの後継対応の事実）なので、`aggregate_to_base` / `crosswalk` / `reconcile` は
分類軸のコード列（`area_code`/`base_code` 以外の `*_code`）を自動判別し、group/ソートキーと
「総数スライス」（全 `*_code`=="0"）をそこから構成する。よって by_age は**キーを手足しせず**そのまま
乗る（`sex_code` のみ→`sex_code`+`age_class_code` に追従）。設計原理は共有ディメンションの
[area_master.md](area_master.md) を参照（重複記載しない）。

## 検証（保存則）— 2 段構え

1. **国民保存（既存 `national_conservation` を流用）:** 各年「アトム合計(age=総数,sex=総数) == 全国total」。
   総人口は `population` と同値なので、1980 の 37 人差（特別区部・区未定分）も同様に `KNOWN_DIFFS` で受容。
2. **年齢保存（新規・age_class 固有）:** 全地域・全年で **年少+生産+老年+不詳 == 総数**。
   不詳を導出注入しているため恒等的に成立するはず＝**回帰検知用のガード**として test に固定する。
   併せて男女保存（男+女 == 総数）も同様に確認できる。

`population_by_age` の `age_class_code=0`（総数）スライスは現行 `population` と一致する（全9年で全国値 diff=0 を実証済み）。

## 兄弟ファクトの実現可能性マップ（ロードマップ）

この表は **「星座に足す候補の話題 × それを市区町村×経年で安く作れるか」の判定表**（本 fact の
内容ではなく、次に何を作れるかのロードマップ）。安く作れるかは **e-Stat「時系列データ」製品が
存在するか**でほぼ決まる（総務省が経年比較用に整形済み＝各年 cleaner 1 個で足りる）。無い話題は
各年基本集計の自前ハーモナイズ（population 本体並みの高コスト）になる。

| 話題（ファクト候補） | 市区町村×経年         | 根拠＝e-Stat「時系列データ」グループ              | 状態                                                         |
| -------------------- | --------------------- | ------------------------------------------------- | ------------------------------------------------------------ |
| 年齢3区分×男女       | ○                     | 男女，年齢，配偶関係                              | ✅ 実装済（本書）                                            |
| 昼夜間人口           | ○（1990-2020）        | 従業地・通学地                                    | ✅ 実装済 → [daynight_population.md](daynight_population.md) |
| 配偶関係             | △（時系列は全国のみ） | 男女，年齢，配偶関係（※配偶関係表は市区町村なし） | 見送り（各年基本集計の自前ハーモナイズ＝高コスト）           |
| 労働力・産業・職業   | ×（都道府県止まり）   | 労働力状態，就業者の産業・職業                    | 未（同上）                                                   |
| 世帯                 | ×（都道府県止まり）   | 世帯                                              | 未（同上）                                                   |

> グループ名は e-Stat の `STATISTICS_NAME`（例: 「時系列データ 男女，年齢，配偶関係」）に一致。
> 同じグループでも**表単位で地域粒度が違う**点に注意（例: 「男女，年齢，配偶関係」グループの
> 年齢・男女表は市区町村まであるが、配偶関係表は全国のみ）。

> 「人口等基本集計」という名称は 2010 年以降だが、等価物「第1次基本集計」は 1980 まで遡って存在する。
> ただし年あたり数十〜数百のクロス集計表の集合で **era 毎にスキーマが違い経年比較用に整っていない**。
> 経年比較したい話題は**まず「時系列データ」製品を優先**し、無い話題だけ基本集計の自前ハーモナイズを覚悟する。

# area_master — 地域マスタ（アトム軸スタースキーマ）

星座型アーキテクチャが全ファクトで共有する**地域ディメンション（conformed dimension）の正典**（合併畳み込み aggregate_to_base / crosswalk・人口保存/孤児検証・overrides 運用）。  
特定のファクトに属さず、合併をまたぐ市区町村の連続時系列を成立させる**共有ハブ**として、全ファクト（[population](population.md) / [population_by_age](population_by_age.md) / 将来の兄弟ファクト）から参照される。

> 共通の位置づけ・関連ドキュメントは [forged-dataset-catalog.md](forged-dataset-catalog.md)。

> **なぜファクトから独立させるか:** 地域集合が年で変わる問題（合併・政令市移行・DID等）はどのファクト（総人口・年齢別・世帯…）にも共通で、grain に依存しない。  
> 1 ファクトの doc に埋めるとハブが二重化するため、conformed dimension として 1 箇所に正典を置く。

> 本 doc は `distributions/`（精製データカタログ）に同居するが、それ自体が配布データセットなのではなく、各データセットが依存する**内部の共有ハブ**の設計を記す。
> 各機構の実装詳細（関数契約・選択規則・スキーマ）は `area/*.py` の docstring、CLI コマンドは `data-forge --help` が正典で、本 doc は「なぜ必要か・何を保証するか（検証結果）」に絞る。

## 多年化の知見（地域マスタが必要な理由）

生テーブルの地域表現は年で不統一で、set 演算だけでは時系列として成立しない。具体的には:

1. **area 属性が年で非互換:** `area_level` の意味が違い（2005: level3=市区町村/4=区、2020: level4=市/6=市区町村）、`area_name` の表記も違う（2005「北海道札幌市」/2020「札幌市」）。年またぎで信頼できるのは `area_code` のみ。
2. **旧市区町村の埋め込み方が違う:** 合併前自治体を 2005 は letter付コード（例 `0120A (旧 函館市)`）で、2020 は level7 で特掲。set 演算では旧コードの人口を**後継自治体へ集約できない**。
3. 平成大合併は 2005 の調査時点(2005/10)で大半が完了済みのため、2005 起点では合併が捉えにくい（2005にあり2020に無いコードは93件）。**遡及するほど合併前の自治体が増え、畳み込み（連続時系列）の価値が本領を発揮する**（1980=3278・1985=3276・1990=3268・1995=3255・2000=3252 アトム → 2020=1741 へ集約） → 地域マスタで 1980〜2020 を接続済み（人口保存 孤児0・diff=0 を検証。ただし 1980 のみ 37 人差＝下記の特別区部「区未定分」）。

→ 実用グレードの連続時系列には **地域マスタ（アトム軸スタースキーマ）** が必要。
fact=各年の「標準的な市区町村」による最finest分割（アトム）、dim 相当=合併イベントによる rollup。
「生」の簡易オプション（union/intersection/grid、[population.md の正規化モード節](population.md#派生データセット複数年結合の正規化モード)）はそのまま残す。

## 設計 — アトム軸スタースキーマ

**核となる考え方:** 年ごとに変わる地域集合を、履歴型 dim（有効期間・後継）で持つのではなく、**fact 側を「国土をちょうど1回だけ覆う標準的な市区町村ユニット（アトム）」に固定**し、合併の後継対応は **events（廃置分合イベント）** に切り出す。
各年アトムを基準年へ前方 rollup することで、合併をまたいで正しく畳んだ連続時系列が得られる。

以下は抽象レイヤごとの意味論のみを記す。

### fact 層 — アトム（標準的な市区町村）

各国勢調査年の `area` 階層から finest 分割の葉集合を抽出し、全年で「標準的な市区町村」に統一する。
政令市は市1ユニット／東京23特別区は各1で特別区部 `13100` 集計行は除外／「旧内訳」は二重計上ゆえ除外。
葉集合の選択規則・依存境界は `atoms.py`。

### dim 相当 — 合併イベント（rollup）

合併の後継は fact でなく events 側に持つ＝**実効イベント = parsed ⊕ overrides**。parsed は e-Stat「廃置分合等情報」の生CSVを `history/ingest.py` で正規化したもの（生CSV列は e-Stat 実物で確定済）、overrides は人手クッション（＝堀本体。同一 `old_code` で parsed を置換／`successor_code` を空にした行で無効化）。
各年アトムを施行年 ≤ base_year の events で推移閉包 rollup する（`events.py`／`mapping.py`）。
境界変更・分割・改称は人口保存を崩す/別扱いのため overrides 側で個別対応。

### 集約ビュー — 畳む/畳まないを配布時に固定しない（時間軸）

同じ rollup を2ビューで提供する（`aggregate.py`）:

- **`aggregate_to_base`** … 各年アトムを `base_code` へ前方 rollup し `(base_code, year, sex)` で合算した確定ビュー（単年 fact と同じ8列・`name`/`level` は base_year 時点で統一）。
- **`crosswalk`** … 畳まず後継コード列 `base_code`＋`base_name` を同梱（10列）。`GROUP BY base_code` すれば `aggregate_to_base` と一致する。

畳む/畳まないの選択を配布時に固定せず、利用者の集約クエリへ委譲できるのが利点。

> **2025 投入時の耐性:** `base_year` は集約パラメータに外出ししているため、次の調査年投入時は現 partition に新年 fact を union し新イベントを追記するだけで済み、過去に配布した時系列の基準年ビューは据え置ける。

### 空間集約 — 都道府県 / 地方（空間軸）

合併 rollup（時間方向）と**直交する**行政階層の上位集約（`spatial_rollup.py`）。
市区町村は都道府県を跨がないため **events 非依存**で、`aggregate_to_base` の前後どちらに適用しても同値（県内合計は下記 national_conservation が保証する不変量）。

- `prefecture` … `area_code[:2]+"000"`・`area_level`=2・47 都道府県マスタ `_PREFECTURES`（従来 dashboard 側に埋めていた県名マスタ＋集約 SQL をパイプへ昇格し一元化）。
- `region` … 標準8地方区分（三重=近畿・沖縄=九州）で `R1`〜`R8`・`area_level`=0（全国=1 と都道府県=2 の間の合成集約層）。
- 分類軸（sex/age/daynight）は `_cat_code_cols` で保持（3ファクト共用の無改修一般化）。

**配布物:** 3ファクト（population / population_by_age / daynight_population）が県粒度を `default_join="prefecture"` で固定した専用データセットを持ち（市区町村時系列と upstream 共通・stem だけ分離した派生ビュー）、dashboard が素の射影で consume する（従来ダッシュ側に3重で埋めていた県集約 SQL＋47行 VALUES 県マスタを撤廃し `_PREFECTURES` に一元化）。`region` は現状 dashboard 未使用のため未登録。

## 検証結果（保証する不変量）

`reconcile.py` の2検査で担保する＝**national_conservation**（各年「アトム合計 == 全国total」＝アトム抽出の健全性）と **orphans**（base_year までに消滅したのに rollup 先が base_year に無いアトムを人口降順で列挙＝堀に埋める候補）。
events 未整備の現状は **615件**（2006の大量合併＋政令市移行）。

- **人口保存:** 全9統計（1980〜2020）で「アトム合計 == 全国total」を確認、diff=0 は8年で成立（1980=3278自治体, 1985=3276, 1990=3268, 1995=3255, 2005=2239, 2020=1741=1718市町村+23特別区）。**1980 のみ 37 人差**＝東京都特別区部の集計値(8,351,893)が23区合計(8,351,856)より 37 人多い**区に按分されない「区未定分」**（市区町村グレインに受け皿が無く、捏造せず原資料の真実を保持。`KNOWN_DIFFS={1980:37}` で受容しテスト固定）。
- **県/地方合計:** 全3ファクトで「合計 == 全国total」を全年 diff=0 確認。スポット: 東京都 2020=14,047,594・大阪府 2020=8,837,685・北海道地方 2020=5,224,614（いずれも公表値一致）。
- **遡及 overrides は2類型のみ**（各行の根拠は [events_overrides.csv](../../data/area/events_overrides.csv) のインラインコメント）＝① 行政区への編入 → 政令市補正（政令市アトムは「市1ユニット」ゆえ区への編入を市へ寄せる。例 `34108→34100`）／② 郡区域変更に伴うコード変更（ingest が「郡区域変更」を無視するため 1 段補うと後段の合併/現存は parsed 側で連鎖解決。例 `09381→09410` 塩原町）。

各年の遡及結果（人口保存＝アトム合計 vs 公表全国total、孤児＝rollup 未到達アトム）:

| 年   | 追加 overrides | 孤児 | 人口保存 diff |
| ---- | -------------- | ---- | ------------- |
| 2000 | 6              | 0    | 0             |
| 1995 | 0              | 0    | 0             |
| 1990 | 1（古殿町）    | 0    | 0             |
| 1985 | 0              | 0    | 0             |
| 1980 | 1（塩原町）    | 0    | **37**        |

## 運用 — 配置と再利用境界

| ファイル                                     | 場所                                      | 扱い                 |
| -------------------------------------------- | ----------------------------------------- | -------------------- |
| 生履歴CSV（廃置分合）                        | `data/raw/history/`                       | .gitignore・再取得可 |
| `events_parsed.csv`（ingest 出力）           | `data/area/`                              | .gitignore           |
| `events_overrides.csv`（人手クッション＝堀） | `data/area/`                              | .gitignore           |
| ひな形                                       | `area/seeds/events_overrides.example.csv` | コミット対象         |

> **運用上の注意:** data 側は Git 履歴に残らないため、堀そのものである `events_overrides.csv` は別途バックアップ/私的バージョン管理を推奨（喪失＝堀の喪失）。両ファイルが未配置/空でも `aggregate_to_base` は畳み込みを行わず union と同じ結果になる（データ欠落は起こさない安全側の挙動）。

**再利用境界:** area 層は combine と同格の**データセット非依存**の参照層で、`cli.py` が clean→atoms→combine(union)→aggregate と配線する（combine と相互非依存）。ただし**ソース非依存ではない**（アトム抽出は各ソースの area 表現に依存＝現状は e-Stat 前提。JIS コード軸で揃う events は他ソースでも使い回せる核）。依存の向きの原則は [docs/pipeline-architecture.md](../pipeline-architecture.md) を参照。
